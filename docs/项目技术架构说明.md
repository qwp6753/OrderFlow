# 技术架构

## 结构
模块化单体，前后端分离。backend 按 auth、catalog、orders、inventory、common、config 分包，Controller 接收已校验 DTO；具体 Service 直接实现业务，Mapper 使用 MyBatis-Plus。数据库负责唯一性和外键，关键写入用 Spring 事务。不存在无意义 Service 接口层。

前端 Vue 3 + Vite + JavaScript，Element Plus 负责表单和表格；Pinia 存当前用户，Vue Router 管登录路由，Axios 统一携带令牌及反馈错误。登录令牌使用 sessionStorage，生产必须 HTTPS、严格管理脚本来源以降低 XSS 风险；前端退出是客户端退出，令牌在两小时有效期内仍可能使用，不宣称服务端吊销。

JWT 采用 Spring Security OAuth2 Resource Server 与 Nimbus HS256，校验签名、issuer 和过期时间。每个请求读取账号状态和数据库角色；禁用账号与角色变更立即生效。角色不信任客户端提交值。BCrypt 使用框架编码器，登录由 AuthenticationManager 处理。

## 版本
Java 编译目标21；Spring Boot 3.5.7、MyBatis-Plus 3.5.15、springdoc 2.8.14、Lombok 1.18.42。具体前端版本固定在 package.json 与 package-lock.json。使用稳定正式版本，不使用 Snapshot。
兼容依据：[Spring Boot 3.5](https://docs.spring.io/spring-boot/3.5/system-requirements.html)、[MyBatis-Plus Boot3 安装](https://baomidou.com/en/getting-started/install/)、[springdoc 兼容矩阵](https://springdoc.org/v2/faq.html)。选择已发布的固定版本，非追逐最新。

## 接口约定
成功 HTTP200：{code:"OK",message:"成功",data:...}；错误采用相应 HTTP 状态与相同信封，data=null。
400 参数错误，401 未认证或登录失败，403 角色禁止，404 记录不存在，409 唯一性/关联约束冲突，500 内部异常（服务日志记录，响应不泄露 SQL/堆栈）。不逐层捕获异常或伪造成功。

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | /api/auth/login | username/password 换取 token 和 expiresIn |
| GET | /api/auth/me | 当前用户与角色 |
| GET | /api/admin/users | 管理员查询用户，不返回密码哈希 |
| GET | /api/products | page/size/name/status；返回 MyBatis 分页 records/total |
| POST | /api/products | 创建商品：name/description |
| GET, PUT | /api/products/{id} | 商品详情/编辑 |
| PATCH | /api/products/{id}/status | 上下架：status |
| GET, POST | /api/products/{id}/skus | 规格和库存查询 / 创建 SKU |
| PUT | /api/products/{id}/skus/{skuId} | 修改编码、规格、价格、启停状态 |

第二阶段订单接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | /api/orders | recipientName/recipientPhone/recipientAddress/remark/items；items含skuId/quantity |
| GET | /api/orders | page/size/orderNo/status/from/to，完整编号与包含边界时间筛选 |
| GET | /api/orders/{id} | 返回order、items、movements、shipment，快照、流水及物流信息 |
| POST | /api/orders/{id}/simulate-payment | 仅待付款→待发货，内部模拟、不接真实支付 |
| POST | /api/orders/{id}/cancel | 待付款/待发货→已取消，释放预占、不执行资金退款 |

库存不足、不可售、非法状态返回409；重复SKU或非法参数400。订单读允许三种角色；创建/付款/取消/模拟收货仅ADMIN/OPERATOR，发货仅ADMIN/WAREHOUSE。

SKU 请求：code/name/price/status。状态固定 ON_SALE/OFF_SALE。分页 size 最大100。
OpenAPI UI：开发环境 /swagger-ui/index.html，JSON /v3/api-docs。生产关闭两者。

## 环境与边界
application.yml 公共配置，dev 启用接口文档和账号初始化，prod 关闭文档且必须配置前端来源。DB_PASSWORD、JWT_SECRET 必需；DEV_SEED_PASSWORD 仅 dev 必需。示例 .env 不会自动加载，实际变量通过 shell/IDE 设置。
开发 Vite 将 /api 转发到8080；生产同域反向代理 /api 并配置 SPA history fallback。跨域仅允许显式来源，无任意来源通配符。JWT 放 Authorization 头，无 Cookie 会话，关闭 CSRF。

## 验证策略
JUnit + MockMvc 启动完整 Spring 上下文，以 H2 MySQL 模式执行 Mapper、事务和权限测试，不 mock 已实现的业务。MySQL 仍需单独验证排序规则、约束和方言，不能用 H2 通过替代 MySQL 结论。前端执行生产构建，浏览器联调结果单独记录。依赖缓存与构建输出留在 .runtime/target/node_modules，均忽略 Git。

## 第二阶段事务与前端复用
OrderService具体类管理订单、订单行、库存预占/释放与流水的单库事务，不引入Service接口、锁中间件或通用账本。状态竞争由WHERE状态条件更新决定。库存数量不新增字段，继续使用quantity/reserved_quantity。锁定读取库存余额时使用FOR UPDATE，不能用创建事务早期的一致性快照代替。

前端AppLayout提取原侧栏和顶栏供商品、订单共用，商品表单与API行为保留。订单页面按路由懒加载，共享固定状态展示映射；创建页面提交skuId/quantity和收件信息，不传可信金额。价格与库存展示是估算，后端提交结果为准。

同一套11个订单场景复用于H2和MySQL，无业务Mapper mock。MySQL测试只接受ORDERFLOW_MYSQL_TEST_URL等专用环境变量，且库名必须以_test结尾，清理仅针对该库；不配置时明确跳过。实际运行见第二阶段验收记录。

## 第三阶段接口与事务
| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/inventory | page/size/keyword，按商品名称或SKU信息查库存 |
| GET | /api/inventory/movements | page/size/skuId/skuCode/type/from/to，库存流水分页 |
| POST | /api/inventory/{skuId}/receipts | quantity正整数、remark（可空字符串），ADMIN/WAREHOUSE入库 |
| POST | /api/orders/{id}/ship | carrier/trackingNo，ADMIN/WAREHOUSE发货 |
| POST | /api/orders/{id}/complete | ADMIN/OPERATOR后台模拟确认收货 |

OrderService沿用状态条件更新、排序库存操作和原流水实体，扩展SHIP变动，不重复实现订单体系；InventoryService仅实现入库与查询，InventoryQueryMapper负责现有表JOIN的分页读模型，无通用账本框架。

发货先竞争订单行，实物/预占同步扣减、SHIP流水和shipment写入同一事务；取消仍只接受付款/待发货状态，完成仅已发货且不操作库存。入库用容量条件UPDATE防止INT溢出，再记录真实余额。普通库存不足/状态错误返回409；不可预期数据库失败由已有全局机制返回错误并回滚，不新建多层异常映射。

Jackson关闭浮点向整数的自动截断，保证1.5不能作为库存数量或购买数量。依赖、认证模块及JWT机制保持原样。库存页面用两个页签展示库存和流水，以watch监听当前页签值，覆盖用户点击和程序跳转而不重复请求。订单详情复用现有布局与角色状态，增加物流弹窗、物流记录和模拟收货。

测试扩展为24个订单/库存场景同时跑H2与MySQL，保留原有8组认证商品回归。用于制造流水写入失败的测试临时CHECK约束仅作用于专用_test库，测试账号额外需要该测试库ALTER权限，业务账号仍仅CRUD。
