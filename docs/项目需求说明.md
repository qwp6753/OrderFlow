# OrderFlow 项目需求说明

## 定位与范围
面向中小企业内部运营和仓库人员的 OMS + WMS Lite，展示业务建模、Java 后端与全栈能力。独立于影院毕业设计。采用单企业、单仓库模型，不做多租户、支付网关、消费者商城、部分发货和拆单。

第一阶段交付登录认证、固定角色接口权限、商品/SKU 管理、只读库存查询与 Web 后台。第二阶段实现订单与预占/释放；第三阶段实现单仓入库、仓库发货和模拟确认收货，售后退款仍仅保留后续模型。

## 第一阶段验收
- 正确口令登录获得有时效 JWT；错误账号/口令统一返回401，不暴露账号是否存在。
- 未登录、无效/过期令牌不能访问受保护接口。仓库用户不能修改商品或 SKU；运营不能访问管理员用户接口。
- 密码 BCrypt 存储，响应不包含密码哈希；开发账号密码由环境变量提供。
- 商品名称必填，支持分页、名称包含匹配及上/下架筛选。新商品默认下架。商品上下架和 SKU 启停独立；后续下单必须同时满足商品上架及 SKU 启用。
- SKU 编码全局唯一，仅允许字母数字及下划线/短横线（MySQL 默认排序规则不区分大小写）。价格为正，最多两位小数；编辑不会修改库存。
- 创建 SKU 同事务创建零库存。界面显示实物、预占、可用量，可用量=实物-预占。第一阶段无库存修改入口，也不允许删除有业务关联的商品或 SKU。
- 前端仅使用真实接口，提供表单校验、加载态与错误提示，退出清除当前浏览器会话令牌。

## 第二阶段订单规则
订单状态：PENDING_PAYMENT（待付款）、PENDING_SHIPMENT（待发货）、SHIPPED、COMPLETED、CANCELED。创建即预占并进入待付款；模拟付款仅允许待付款→待发货；待付款/待发货可取消并释放预占。已取消、已发货或已完成不能付款或取消。重复取消返回409且不重复释放。

模拟付款只作内部演示，不连接真实支付。已模拟付款的待发货订单允许取消，但只释放库存，不执行资金退款。第三阶段已增加发货与后台模拟确认收货接口。

一单最多50个不同SKU，每项数量1至1000000；重复SKU要求合并后提交。收件信息必填，备注可为空字符串。金额由后端当前可售商品/SKU价格计算，订单行保存商品名、SKU编码/名称和单价快照。前端不能指定金额。整单金额不得超过DECIMAL(14,2)范围。库存任一项不足返回409，整单与已预占项、流水均回滚。

支持完整订单编号、状态、创建时间起止筛选及分页、详情和订单关联库存流水；三种角色可查，管理员与运营可写。创建时间筛选包含边界，起始不能晚于结束。

## 第三阶段履约规则
仅待发货订单可提交物流公司和单号发货，同一订单只成功一次；同时扣实物和预占，可用量不再重复扣减。多SKU任意失败整体回滚。已取消不可发货，已发货不可取消，只有已发货可后台模拟确认收货并记录完成时间，不再变更库存。

单仓入库允许管理员及仓库人员对SKU增加正整数实物库存并写备注；入库和流水一致提交。库存和流水分别支持分页，流水支持SKU、业务类型、时间筛选。支持RECEIPT/RESERVE/RELEASE/SHIP，不开发采购单、货位、多仓及退货入口。

## 后续业务规则

单仓库存以条件 UPDATE 或行锁保证数量与预占不越界，库存变更和流水在同一事务；流水 business_key（操作类型+业务行ID）唯一保证同一次业务操作不重复记账。不能先查询后无条件扣减。流水包含变更量及变更后数量，用于审计对账。

单订单一次完整发货，发货记录与订单一对一。退货 REQUESTED → APPROVED/REJECTED；APPROVED → RECEIVED，验收入库后记录退款应付金额，不对接真实支付。退货明细必须属于原订单，累计退回数量不能超过已发货数量；后续实现时在事务内锁定原订单明细核验，避免并发超退。

## 非功能要求
外部输入校验、接口鉴权、事务、唯一约束和错误反馈是必要保障。默认关闭生产文档，不硬编码凭证，不引入 Redis、消息队列或微服务。测试应区分 H2 自动化验证与 MySQL 实际验证。
