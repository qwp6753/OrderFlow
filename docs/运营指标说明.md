# 运营指标说明

日期采用 Asia/Shanghai 自然日，选择的开始和结束日期都包含在区间内。SQL 查询边界为 [开始日零点, 结束日次日零点)，最长 366 天。趋势中的空白日期补零。

| 指标 | 时间和计算口径 |
|---|---|
| 订单总数及当前状态分布 | 按 sales_order.created_at 筛选，包含所有订单状态。每个订单只计一次 |
| 每日新建及完成订单数 | 分别按 created_at、completed_at 分组。完成订单要求当前状态 COMPLETED |
| 模拟成交总额与趋势 | COMPLETED 订单在 completed_at 区间内的 total_amount 快照之和，从订单表直接汇总 |
| 售后申请数、状态分布、待处理单数 | 按 return_request.created_at 筛选。待处理为当前待审核及待验收之和 |
| 期间完成退货单数及件数 | 按 received_at 筛选 COMPLETED 售后。单数按不同售后单计数，件数汇总 return_item.quantity |
| 已完成退货预计退款额 | 同一批已验收退货的原 order_item.unit_price × 退回件数。申请、拒绝、待验收不计入 |
| 模拟净成交额 | 期间模拟成交总额减去期间已完成退货预计退款额。跨期退货可能让期间净额为负 |
| 商品与 SKU 排行 | 销量按订单完成日期，退货按验收日期分别汇总，再按商品或 SKU ID 合并。净销量为两者之差。完成销量降序取前 10，同销量按 ID 升序。显示参与统计的最大订单明细 ID 所保存的名称与编码快照，商品归属沿用 SKU 的商品外键 |
| 当前库存与预警 | SKU 总数及实物、预占、可用总量。可用 = 实物 − 预占，严格低于 LOW_STOCK_THRESHOLD 的 SKU 进入预警。默认阈值 10 件，预警分页按可用量从少到多排列 |

已完成历史记录若缺少完成或验收时间，仍可按创建时间纳入状态分布，相应金额及完成趋势不使用推测日期。第五阶段的订单、售后相关新时间写入明确使用上海时区，已有 DATETIME 值按原样统计。

订单金额不与明细联表累加。销量 SQL 分开产生销售与退货记录再聚合，多条售后不会放大销量及金额。看板查询通过只读一致性事务汇总，库存预警分页独立读取当前数据。

接口为 GET /api/analytics/dashboard 和 GET /api/analytics/low-stock，仅 ADMIN 和 OPERATOR 可访问。数据来自现有业务表，无新增统计表、索引或迁移。金额仅为模拟统计，不代表实际收款、退款或现金收入。

## 本地验收

Java 21 后端打包成功，74 项通过，其中真实 MySQL 8.0.44 为 33 项，失败和跳过均为 0。Vue 构建成功，Edge 全套 9 项通过，最终看板用例再次通过。集成数据覆盖多 SKU、取消、历史改价、跨期退货、多次部分退货、拒绝、空日期、阈值边界和角色隔离。
